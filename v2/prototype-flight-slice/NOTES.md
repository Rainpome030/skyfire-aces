# 原型裁决记录

验证问题：哪种镜头与高度表达，能让有限操作的俯视空战同时保持舒适、可读和有战术选择？

## 镜头裁决（2026-08-18）

- **胜出方案：A——地图朝上 + 世界方向稳定 + 低 FOV 透视。**
- 用户原话：“A和C都很好，我决定采用A”。
- C 的体验获得正面评价，但没有被采用；不得把它记成失败方案。
- B 没有收到明确评价，不从沉默推断负面结论。
- 落选变体与切换器已经从原型删除。

镜头选型已经完成。正式 v2 应重写并保留 A 的设计规则，不应直接把本原型代码当成生产实现。

## 仍待验证

- 高度可读性：自动化可见，仍需真人在手机上确认无需读数也能判断
- 有效战术决策：已加入突入路线、编队夹击和交叉猎场，仍需观察玩家是否理解并主动利用
- 自动机炮与主动导弹的职责边界：已改为五发短点射/持续扫射回报，以及 `LOCK`/`PERFECT` 两级四发限量导弹，仍需真人调数值

## 展示版实现记录（2026-08-19）

已完成但仍需真人试玩验证：

- 将一个海域组织成低空突入、高空拦截、交叉猎场三段，不增加新的常驻操作。
- 雷达负责暴露提示、防空炮只威胁低空、截击机与王牌只在高空有效攻击。
- 保留地图朝上、低 FOV、缓动跟随；竖屏仅调整镜头距离，不随转向旋转地图。
- 用模型轮廓影子、立体云层与穿云透明度表达真实高度关系。
- 加入更明确的拖尾、导弹飞行、命中碎片、雷达扫描、防空预警和高度扫描线。
- 防空锁定被高度动作甩开时产生独立擦身反馈，防空重击使用区别于普通受击的双脉冲反馈。
- 加入启动简报、三阶段任务轨、任务结算与复盘指标。
- 完成桌面、手机竖屏与手机横屏布局；触屏只保留高度与导弹按钮，战场左右半区负责转向。
- 最近目标的数据链方位与距离提示避免手机窄视野下变成无方向盲飞。
- 所有当前运行时模型均采用 CC0 来源，来源与导出记录见 `public/THIRD_PARTY_ASSETS.md`。
- 将飞机全部替换为 CC0 的 F-14、Rafale B 和 F-15 轮廓；保留手机友好的低面数，同时显著提高辨识度。
- 雷达链路会缩短防空锁定并扩大有效射程；预告期间持续计算玩家航线，开火后形成真实飞行的炮弹。
- 截击机分成长机与僚机，王牌在半血后进入更快的第二阶段；敌弹、擦身和重击均有独立状态链路。
- 导弹改为四发限量、持续锁定后手动发射；加入一次救援、阶段清场停顿、突入路线奖励和结算评级。
- 索敌拆成 360° 雷达接触、±100° 软捕获、±75° 武器锁定和 ±25° `PERFECT` 解算；同一目标会黏着保留，错误高度层仍显示 `CHANGE ALT`。
- 手机转向在目标附近加入轻量火控摩擦，强输入仍能挣脱；导弹按键支持锁定前短输入缓冲，不增加任何新按钮。
- 加入 W/S 能量机动：W 加力延伸并扩大转弯半径，S 用速度换短时高转向率，松开后自动回巡航；高度仍由 Space 离散切换，没有加入特技按钮或额外资源条。
- 截击机与王牌开火后进入短暂攻击承诺，不能瞬时贴身跟转；玩家用 S 配合转向迫使其冲过头，可获得短暂 `ADVANTAGE` 并加快火控解算。
- 手机战场输入改为动态二维操纵区：水平控制转向，向上控制加力，向下控制减速急转；高度与导弹仍是仅有的两个触屏按钮。
- 导弹伤害从“按键立即结算”改成模拟层中的离架、点火、制导、碰撞与脱靶；普通 `LOCK` 和 `PERFECT` 使用确定性的不同制导与杀伤参数。
- 自动机炮改为左右炮口交替的五发点射；持续保持小角度射击窗口会获得独立 `GUN RAKE` 命中、短暂压制与视觉反馈。
- 按展示需求刻意未加入任何声音。

自动化只能确认功能和布局没有明显破坏，不能替代以下真人试玩结论：眩晕程度、无需读数字的高度判断、三阶段节奏是否过长，以及自动机炮是否夺走过多成就感。

## 有限输入机动语法（2026-08-19）

本轮原型问题：**只用转向轴、W/S 能量轴和 LOW/HIGH 高度命令，能否让玩家自然做出可识别、能改善交战几何的机动，而不是增加特技按钮？**

当前实现答案是“逻辑上可行，手感仍待真人裁决”：

- 空中敌机不再固定在 HIGH 层。长机、僚机和王牌拥有连续高度、垂直速度与各自的纵向航线；攻击承诺会锁定一个真实三维预测点。
- 空中火控按实际高度差判断，同一个 LOW/HIGH 命令会随着目标高度产生不同结果；地面火力仍只覆盖低空。
- 系统根据交战结果识别 Boom & Zoom、高/低悠悠、防御滚转、反转、剪刀机动与抢先转弯。单纯按键序列不会直接成立。
- 防御滚转要求敌机正在建立攻击线，同时做 S 急转与高度转换，并最终真的迫使敌机冲前；没有无敌帧。
- 反转和剪刀机动要求冲前之后改变转向方向，并在近距内形成第二次反转；悠悠要求完成高度往返且角度或距离确实改善。
- 识别结果只给予短暂火控优势、得分、HUD/拖尾反馈和 AAR 记录，不接管飞机、不播放自动特技。
- 纯识别器位于 `src/core/maneuvers.ts`，不依赖 Three.js 或 DOM；运行状态同时暴露在 HUD 与 `window.__skyfireSlice`。
- 试玩反馈否决了高度切换时从上到下扫过屏幕的横线，该全屏效果已删除；高度运动改为带加速、反向制动和到点收势的连续曲线，穿云透明度也不再跳变。

自动化已确认六条识别路径可达，原有 24 项模拟测试、构建和三视口 smoke 仍通过。下一步必须由真人完整玩第二、三阶段，判断：(1) 机动是否能在不看文字时被理解；(2) 触屏能否稳定做出 S + 转向 + 高度切换；(3) 识别阈值是否过严或能被刷分；(4) 敌机纵向运动是否足够帅但不重新引发眩晕。
