# Three.js 飞行切片原型

> **PROTOTYPE — 可丢弃代码，不是正式 v2。**

原始验证问题：**哪种镜头与高度表达，能让有限操作的俯视空战同时保持舒适、可读和有战术选择？**

## 镜头裁决（2026-08-18）

- **采用 A：地图朝上 + 世界方向稳定 + 低 FOV 透视。**
- 用户反馈 A 与 C 体验都很好，最终选择 A。
- C 是可行备选而非失败方案；B 未收到明确负面评价。
- B、C 和原型切换器已删除，后续 Agent 不应重新打开镜头选型，除非出现新的试玩证据。

本目录仍是用于验证高度、操控和战斗关系的可丢弃切片，不能直接提升为正式 v2。2026-08-19 的展示版把验证内容组织成一个约三分钟的完整单关，但没有把原型误升格为生产架构。

## 运行

```bash
cd v2/prototype-flight-slice
npm install
npm run dev
```

打开 `http://127.0.0.1:4173/`。

## 操作

- `A / D`：左右转向
- `Space`：低空/高空切换
- `E`：发射导弹
- `R`：重新开始
- 鼠标或手指在战场左右两侧按住：转向

机炮在敌人进入机头射界且高度允许时自动开火。低空可以攻击地面防空炮，但会暴露在防空火力下；高空可以脱离地面火力，却会进入截击机的优势区。

## 单关结构

1. **低空突入**：切断雷达与防空阵地。
2. **高空拦截**：拉升进入双机编队的射击层。
3. **交叉猎场**：在地面阵地与王牌截击机之间主动选层。

桌面与手机使用同一套模拟规则。手机保留两个主动按钮，并用“按住战场左右侧”承担连续转向；竖屏和横屏都有独立 HUD 布局。演习结束后会展示高度切换、导弹命中、承伤和救援复位等复盘指标。

## 验证门槛

- 连续十分钟无明显眩晕。
- 高度在不读数字时仍可由阴影、云层与遮挡判断。
- 玩家会主动利用高度攻击或避险。
- 拖尾说明速度和转向，不淹没战场。
- 地面、普通截击机与王牌形成可以复盘的取舍。

## 自动检查

```bash
npm test
npm run build
npm run smoke
```

`smoke` 会启动本地浏览器，检查桌面、手机竖屏和手机横屏，并更新 `artifacts/A-*.png`。

剩余试玩结论写入 `NOTES.md`。高度、武器与防御规则验证完成后，应把已验证规则重写进正式 v2，而不是直接把本原型提升为生产代码。
