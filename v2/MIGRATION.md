# 《苍穹之翼》正式 v2 迁移边界

## 1. 基准与目标

正式 v2 是现有《苍穹之翼》的 Three.js 演进版，不是 `chi` 原型的产品化副本。

- 现有 `main` 是玩法、内容、存档和兼容行为的产品基线。
- `chi/v2/prototype-flight-slice` 是研究素材：可学习三维战场、远景镜头、航迹、高度切换、射界自动机炮、主动导弹、地面目标、索敌和关卡编排。
- 不从原型目录导入运行时代码，不继承其坐标假设、敌机 AI 或固定三阶段任务结构。
- 每项借鉴都必须按正式 v2 的坐标契约重写，并有动态测试或试玩验收。

产品判断只有两条：操作反馈必须爽，画面和战术关系必须帅且清楚。镜头采用远景、小机体、稳定地图方向，让玩家能读出双方速度、航向、航迹和缠斗关系。

## 2. 不可丢失的现有系统

迁移完成不是“能飞、能打”，而是以下系统在 Three.js 版本中全部可用：

| 领域 | 必须保留的产品行为 |
| --- | --- |
| 飞行 | 油门、转向、速度、高度、侧倾、加力、突进、滚筒、碰撞、受伤、坠毁 |
| 武器 | 现有武器类别、品质、随机武器池、同类武器三合一、异类武器切换、锁定与导弹 |
| 局内成长 | 永久 Buff（射速、移速、血量、幸运、弹药数量等）及本局持续生效 |
| 波次 | 每波结束 Boss；击败 Boss 后暂停并进行武器三选一；始终有“放弃”选项 |
| 精英池 | 第 6 波起从第 1 个五波 Boss 组随机 1 个加入当波精英；第 11 波起从每个已完成五波组各随机 1 个；每波重新抽取 |
| 敌人与内容 | 普通敌机、精英、全部 Boss、地面目标、关卡目标、战役和无尽模式 |
| 同伴 | 僚机的跟随、索敌、射击、受伤/存活及 HUD 表达 |
| 元流程 | 任务选择、简报、机库、战机/难度、章节解锁、评级、成就、结算 |
| 生存与存档 | 复活、局内状态重置、最高记录、解锁与设置持久化、旧存档兼容策略 |
| 输入 | PC 键盘、可绑定鼠标按键、手机竖屏单手操作、暂停和升级界面键盘选择 |
| HUD/设置 | 武器与锁定读条、导弹开关态、Buff、威胁/高度警报、血量、音量、控制与镜头模式 |
| 音画反馈 | BGM、音效、命中/击杀反馈、爆炸、粒子、慢镜、震屏、提示和 Boss 演出 |

同类型不同品质武器遵守合成路线，不得用低品质直接替换已装备的同类高品质武器；不同武器类别仍允许立即切换装备。

## 3. 正式坐标契约

契约实现在 `skyfire-three/src/core/coordinates.ts`，任何模拟、AI、渲染和相机代码都只能通过这一语义沟通：

- 旧版 Canvas `x/y` 映射到 Three.js `x/z`，Three.js `y` 只表示物理高度。
- `heading = 0` 朝世界 `+x`。
- 左转（`A`/左侧触控）产生负角，右转（`D`/右侧触控）产生正角。
- 航向向量为 `(cos(heading), sin(heading))`，分别对应世界 `x/z`。
- 模型机头统一为本地 `+x`；渲染 yaw 为 `-heading`，确保模型朝向与位移一致。
- 物理世界朝上为 `+y`；地图稳定相机的屏幕上方为世界 `-z`，相机不继承飞机 heading 或 bank。

这套规则优先于模型文件的原始轴向。资产加载时应在模型适配节点中校正模型，而不是修改模拟语义。

## 4. 分阶段迁移

### M0：契约和并行外壳

- 建立独立 Vite/Three.js 入口，旧版继续可运行。
- 固化坐标、状态、输入和存档边界。
- 自动测试覆盖左右转向、航向位移、模型朝向、目标方位和相机地图方向。

完成门槛：同一组记录数据在模拟、模型和 HUD 上方向一致；正式版 `main` 无行为变化。

### M1：飞行与远景狗斗切片

- 迁移玩家飞行、速度、高度、侧倾、加力、突进和滚筒。
- 实现远景低 FOV 相机、小机体比例、航迹、阴影和高度可读性。
- 同时支持地图稳定与航向朝上镜头模式。

完成门槛：PC 和手机左右操作无反向；自机不会遮住战术关系；不同高度能从尺寸、阴影或航迹中稳定辨认。

### M2：战斗内核与索敌

- 按正式数据迁移全部武器、子弹、导弹、命中、伤害、品质和合成。
- 借鉴自动机炮射界与主动导弹分工，但保留设置和平台输入适配空间。
- 建立空中/地面目标的统一索敌接口，明确射界、遮挡、距离和优先级。

当前迁移分支已落地第一版只读目标解算契约：

- `v2/skyfire-three/src/core/targeting.ts` 统一计算目标距离、水平夹角、高度差、锁定资格和机炮射击解算。
- 旧玩法的 `CFG.lockRange / lockCone / lockTime` 仍是锁定行为权威，Three.js 只消费快照，不重复修改目标状态。
- 3D 锁定标记按锁定进度显示红（未完成）→黄（进行中）→绿（满锁且进入机炮射界），不会改变旧版武器/导弹输入路径。
- 迁移版桥接已启用自动机炮：敌机进入前向 820 逻辑单位 / 0.5 弧度射界时调用旧 `firePlayerGuns()`；导弹仍需要玩家主动确认，旧武器品质、射速、弹丸数量、弹药和 Buff 结算不复制也不绕过。
- 空中目标和地面目标共享同一目标接口；地面目标的高度窗口和遮挡规则仍属于 M2 后续接入项。

完成门槛：同类合成与异类切换规则测试通过；开火不会因帧率、镜头或模型朝向改变；导弹锁定反馈完整。

### M3：敌机 AI、Boss 与关卡设计

- 重写普通敌机、精英、Boss、地面防空和任务目标，不复制原型追击权重。
- AI 以“进入、接敌、攻击、脱离、重新占位”的显式状态工作，避免贴脸反向绕飞。
- 借鉴 `chi` 的空地威胁、高度窗口和阶段编排，重新服务于现有战役与无尽内容。

完成门槛：敌机航向与位移一致；接近时能脱离再攻击；所有旧关卡目标可完成和失败；关键 AI 有确定性测试。

### M4：成长、波次与僚机

- 接入 Buff、武器三选一/放弃、Boss 波次和五波历史精英池。
- 迁移僚机的编队、索敌、开火、伤害和 HUD 状态。

完成门槛：长局跨 15 波自动测试通过；第 6/11 波精英来源与每波重抽正确；升级暂停不会推进战斗时间。

### M5：完整流程、HUD 与输入

- 迁移标题、任务选择、简报、机库、战役、无尽、暂停、结算和设置。
- PC 保留键鼠与鼠标按键绑定；手机只做竖屏单手布局。
- HUD 重新按远景狗斗设计，警报、武器、完整度和触控按钮不互相遮挡。

完成门槛：从启动到结算/重开完整走通；PC 键盘升级四项循环选择可用；主流竖屏尺寸无重叠。

### M6：存档、平台适配与切换

- 定义旧存档升级器，再接 PC Web/桌面封装与微信、B 站、抖音小游戏适配层。
- 将 DOM、存储、音频、输入、生命周期、分享和广告放在平台端口之后。
- 完成性能预算、资源许可、包体和真机测试后才替换默认入口。

完成门槛：旧存档升级可回滚；桌面与至少一个小游戏真机端完成完整一局；稳定版保持可恢复。

## 5. 工程边界

- 模拟层不导入 Three.js、DOM 或平台 API；渲染器只消费状态快照和事件。
- 内容数据不直接操作场景对象；AI 不读取屏幕坐标；HUD 不修改战斗状态。
- Three.js 模型资产统一经过朝向、尺寸、阴影和许可适配。
- 每阶段在独立迁移分支验收，未达到行为与视觉门槛不覆盖稳定 `main` 或 `dist`。
- 自动测试负责方向、数值和流程不回归；“爽”和“帅”必须额外通过实际试玩与桌面/手机截图验收。
